# OpenMOBI 手机和平板实机测试清单

适用于 **0.1.0-alpha.6**，测试器材为白色经典款莫比智能椭圆机 **MB-EP-xxxxxx**；手机为 **小米 14 / Android 16**，平板为 **iQOO Pad 2 Pro / Android 16（以实际诊断 API 36 为准）**。本清单记录待验证项目，不代表这些项目已经通过实机测试。

先在一台设备完成核心流程，再断开连接，换另一台重复。核心流程每台预留约 20–30 分钟，遇到问题即可先反馈，不必做完。其他器材和真实折叠屏本轮记为「不适用」。

每项使用「通过／异常／未测／不适用」记录；有问题时引用编号即可，例如「小米 14，C07 异常」。文末提供可复制的反馈模板。

## alpha.6 本轮复测（界面部分无需连接器材）

先在演示模式完成 E01–E08。反馈写“设备＋编号＋通过／现象”即可，不需要重新测试所有旧项目。

- [ ] **E01 日志默认值**：「设置 → 设备诊断 → 记录蓝牙协议报文」在未主动关闭过时默认勾选。已明确关闭的选择仍保留。导出诊断仍低于 128 KiB。
- [ ] **E02 档位一致性**：演示设备为 24 档，1 档显示 4%，12 档显示 50%，24 档显示 100%。内置方案、我的训练与运动页对同一目标应映射到相同档位；50% 自定义阶段显示 12 档／50%。真实器材按诊断中的最大档位计算。
- [ ] **E03 返回训练**：开始训练后切换到记录、设备或设置，顶部蓝色入口能看清计时和状态，整块可点击并回到同一场训练；暂停后计时不继续增加。
- [ ] **E04 方案库**：搜索名称，按时长、最高阻力目标、来源筛选；收藏后方案置顶，重开 App 仍保留；分组展开／收起，不需要穿过 21 个大卡片找我的训练。
- [ ] **E05 记录查找**：搜索设备名称、设备类型或日期（如 10/2），切换设备／演示来源过滤。列表设备标签清楚，分页前后不重复；点击记录可返回原筛选位置。
- [ ] **E06 统计与详情**：切换周／月／年／全部，核对几条已知记录的时长、热量、次数合计；手机点击「展开趋势」后点击柱状图看数值，收起后能更方便查找记录。详情查看心率、频率、功率、速度、阻力趋势和平均／峰值；缺失值为 —，估算有 ≈。旧记录未保存的方案名称会标为未记录。
- [ ] **E07 归档**：归档一条测试记录，普通列表隐藏、统计总量不变；在归档范围找到并恢复。批量归档先核对筛选条件和确认数量，不需要删除任何真实数据。
- [ ] **E08 文件与布局**：记录菜单导出统计 CSV，用表格软件打开，检查中文列名、日期、时长、单位和每次训练一行。导入／迁移用完整 ZIP 或菜单的原始 CSV。手机／平板横竖屏、深色／浅色和常用字体大小下检查控件及长名称；短屏允许滚动查看详情。

## alpha.5 悬浮窗复测（约 5 分钟）

先确认「设置 → 悬浮窗」的总开关和自动开关已启用、系统权限已授予。在熟悉的低档位下开始一次训练，打开常用视频应用，按以下编号反馈即可；运动主界面继续沿用 alpha.4。

- [ ] **B01 小窗读数**：小窗能看清两项自选指标、当前阶段和剩余分秒。未保存过配置时默认「运动时长＋阻力」；升级保留已选内容，可在显示设置里改回此组合。自由运动没有虚构的阶段倒计时。浅色／深色均检查一次。
- [ ] **B02 展开和控制**：点击小窗展开，试相邻档位加减、暂停和继续。大窗中央档位应等设备反馈后变化；暂停时累计值与阶段倒计时冻结。点「运动界面」回到同一次运动，时间和数据不清零。
- [ ] **B03 位置和横屏**：拖动小窗到视频边角再展开、收起；大窗拖动标题区域。切换视频横竖屏，检查面板留在屏幕内，底部暂停／返回和加减按钮始终可点。低矮横屏允许滑动中间信息区查看全部指标。
- [ ] **B04 自选和文字**：大窗右上角调节图标进入自选指标，应直接选中「大悬浮窗」，也能切到小窗配置。选定内容后再次悬浮，读数与单位完整；长数字不会让窗口变大、跳行，估算符号位于标题后。
- [ ] **B05 视频与后台**：边看视频边运动 3–5 分钟。面板外的触摸不受影响，读数持续更新；回到 App 后悬浮窗隐藏；关闭自动开关后不再自动弹出。异常请附视频应用、系统版本、字体大小、方向和日志。

## alpha.4 优先复测（先在平板完成）

旧日志已确认 alpha.3 能接收变化的阻力和运动反馈。这轮重点检查功率、新运动页和自动悬浮，不需要重做全部项目。

- [ ] **A01 功率**：连接并轻缓踩踏 15–30 秒。在运动页找到「功率 ≈」；手机默认第二页，可通过箭头或滑动切换，也可在显示设置移到第一页。应随频率／实际阻力反馈变化，静止时显示 0 或传感器超时后的 —。记录一个稳定状态下的频率、档位、功率；有官方应用可用时，可对照相近状态。该值沿用官方估算模型，不是新增功率传感器测量。
- [ ] **A02 布局**：平板横竖屏与手机横竖屏各查看一次运动页。计时、当前目标、阶段及最近三段清晰；六项默认指标可见或可翻页。固定底栏始终能暂停、结束保存、手动悬浮；大字体下内容可滚动到全部控件。
- [ ] **A03 阻力**：先轻缓踩踏确认相邻档位反馈，再测试滑块。滑块可停在待确认目标，中央数值仅在器材反馈后改变。自动调阻开关关闭时不应额外变档；手动调阻会退出自动模式。
- [ ] **A04 自动悬浮**：到「设置 → 悬浮窗」，确认「启用悬浮窗」「自动悬浮窗」默认开启，先授权。训练中按 Home／切换视频应用应显示小窗；回到 OpenMOBI 应隐藏并保留同一运动。关闭自动开关后重复操作，不应自动弹出；手动悬浮仍可用。关闭总开关后两者都不可用。请注明 vivo 后台策略是否介入。
- [ ] **A05 常亮和长数字**：运动页停留超过系统息屏时长，检查不自动熄屏。悬浮窗持续运动一段时间，检查数字增长不改变窗口大小、不换行，≈ 位于标题后，档位百分比更小、更淡。
- [ ] **A06 日志**：开启协议报文、最短复现问题后立即导出 report 4；文件应小于 128 KiB。继续运动后再次导出，文件应有固定上限，不再无限变大。「清空诊断日志」只清日志，不删除运动记录。

反馈时按 A01–A06 写“通过／现象／未测”，附设备、方向、字体大小和应用版本即可。

## 测试前准备

- 在「设置 → 应用更新」记录完整 App 版本，并记录手机和平板的系统版本号，例如 HyperOS 或 OriginOS 的版本。两台使用同一版本的 OpenMOBI。
- 已有重要记录时先在「记录 → 导出完整备份」保存 ZIP。升级使用覆盖安装；无需卸载、清除数据或重置器材。alpha.1 用户需手动下载新版，旧版更新检查不能发现此次预发布。
- 退出演示模式，断开官方 App 和另一台手机／平板与器材的连接，唤醒器材。一次只用一台测试机连接。
- 首轮保留系统默认的省电和后台设置；如果出现后台断连，记下当时设置，再尝试放宽限制并对比。不要先同时修改多个系统选项。
- 先验证相邻档位的实际反馈，再测试自动方案。**「暂停」与「结束并保存」不会制动器材，也不保证自动降阻。**若档位反馈或实际阻力异常，先停止踩踏，跳过后续自动调阻测试并导出日志。

## 核心流程

每项分别填写「手机：」「平板：」。数据、截图和日志都应注明来自哪台设备。

- [ ] **C01 安装与离线启动**\
  如安装了官方 App，确认两个应用可以共存。关闭 Wi-Fi 和移动数据，保留蓝牙，重新打开 OpenMOBI，进入训练、记录、设备和设置。\
  通过标准：无需账号、验证码或网络；离线方案与本地记录可以打开。覆盖升级后原有记录仍在；首次安装可跳过升级验证。\
  手机：未测；平板：未测。

- [ ] **C02 搜索并连接椭圆机**\
  在「设备 → 搜索附近器材」允许附近设备权限，找到 MB-EP-xxxxxx 并连接；通知权限出现时也允许。打开「设备诊断」，截图或记录协议、阻力范围与连接状态。\
  通过标准：完成能力读取，显示真实器材而非演示；能收到阻力和运动反馈。若只有「仅监测数据」或按钮灰色，请保留诊断，不将它记为可控通过。记录搜索与连接各用了大约多少秒。\
  手机：未测；平板：未测。

- [ ] **C03 自由运动与基本指标**\
  开始「自由运动」，轻缓踩踏约 1 分钟，观察时长、频率、阻力、距离和热量；若当前没显示某项，在运动页右上角「显示设置」中添加。随后停止踩踏约 10 秒观察变化。\
  通过标准：时长递增，频率随运动变化；距离、热量在运动中累计，停止后不持续按旧速度增长。估算显示 `≈`，缺少的传感器数据显示 `—`。仅停止踩踏不会自动暂停计时，这是当前行为。\
  手机：未测；平板：未测。

- [ ] **C04 手动阻力与百分比**\
  在舒适的低档位记下当前档位，点一次「＋」，等反馈稳定后点一次「−」。再用新增滑块选择附近档位，松手提交，观察目标预览与真实反馈。分别记录请求档位、最终显示档位、等待时长，以及体感是否确实变重／变轻。\
  通过标准：器材实际响应，最终反馈与请求一致；档位和百分比一起更新，不会只把请求值显示成已执行。百分比按已识别范围换算，例如范围 1–24 时，1 档为 4%，12 档为 50%，13 档约为 54%；它不是心率或运动强度百分比。**不用为了测试达到最大阻力。**\
  手机：未测；平板：未测。

- [ ] **C05 暂停与继续**\
  记下时间、距离和热量，点击底部「暂停」，等待约 15 秒，再点「继续运动」。\
  通过标准：暂停期间这三个累计值不增长；继续后接着累计，不清零，也不补算暂停间隔。瞬时踏频等传感器读数可以继续更新。\
  手机：未测；平板：未测。

- [ ] **C06 自选指标与配置保留**\
  在「运动页 → 显示设置」或「设置 → 运动界面」里给主运动页选择时长、距离、热量、频率、阻力、速度等项目，调整顺序；再分别配置小悬浮窗和大悬浮窗。旋转屏幕或返回设置后再进入，检查配置。可分两轮查看全部 17 个选项。\
  通过标准：主运动页最多 12 项，小窗最多 2 项，大窗最多 4 项；三份选择独立保存。页面容纳不下时能左右滑动或点击翻页箭头，数值与单位可见。椭圆机不提供的桨数、坡度等显示 `—`，无需出现虚构数值。\
  手机：未测；平板：未测。

- [ ] **C07 两级悬浮控制面板**\
  点击「悬浮窗」，首次允许系统悬浮权限后返回。依次测试小窗拖动、点击展开、大窗阻力加减与暂停／继续、收起、打开运动界面；重复往返 3 次。\
  通过标准：小窗显示所选信息；拖动不会误展开，点击可展开；大窗显示自己的所选信息和控制；返回的是同一次运动，数据不清零，不出现多个悬浮窗。面板移到边缘后仍能找回并操作。\
  手机：未测；平板：未测。

- [ ] **C08 边看视频边运动**\
  恢复网络并打开常用视频 App，保持悬浮窗轻缓运动约 5 分钟。切换视频横竖屏，操作一次大窗暂停／继续，再返回 OpenMOBI。记录视频 App 名称。\
  通过标准：视频操作不被面板外的透明区域拦截；悬浮窗持续更新且可操作；蓝牙、时长和记录保持连续。若仅在某个视频 App 中消失或不能点，也请注明。\
  手机：未测；平板：未测。

- [ ] **C09 断连与手动重连**\
  停止踩踏，保留正在计时的训练，关闭本机蓝牙约 10 秒，再开启。观察提示，手动重新连接器材，等读数恢复后点击「继续运动」。\
  通过标准：断连后训练暂停，时间和累计值停止增长；恢复蓝牙不会自行恢复运动或重放积压指令；手动继续后仍是同一次训练，累计值不清零、不突增。\
  手机：未测；平板：未测。

- [ ] **C10 结束保存与重开**\
  先记下最后的时间、距离、热量。点击运动页底部「结束并保存」并确认结束，打开「记录」，再退出并重开 App。\
  通过标准：只新增一条对应记录；时长与最后一次显示基本一致，距离和热量在显示精度内一致，估算标记保留；重开后数据仍在。真实器材记录没有演示标记。\
  手机：未测；平板：未测。

- [ ] **C11 内置方案与分段训练**\
  检查训练页有 21 套内置方案，打开「轻度训练」详情，测试「复制并编辑」，确认副本不会改掉原方案。另建下表的 3 分钟测试方案并运行；仅在 C04 已确认实际调阻正常后进行。阶段中暂停约 10 秒；再试手动改一档，然后重新开启「自动调阻」开关。\
  通过标准：倒计时使用「X分X秒」，暂停时冻结；阶段顺序和目标正确。自动调阻逐档接近目标，当前阻力以设备反馈为准；手动操作后不会立即被自动调回，恢复自动后才重新跟随目标。最后一个阶段完成后显示已完成，允许继续自由运动，需自行结束保存。无需逐一跑完所有内置方案。\
  手机：未测；平板：未测。

  | 阶段 | 结束条件与目标值 | 阻力百分比 |
  |---|---|---|
  | 1 | 时间，60 秒 | 5% |
  | 2 | 时间，60 秒 | 10% |
  | 3 | 时间，60 秒 | 5% |

  这是功能验证方案，不是训练处方。百分比映射到整数档位后可能有舍入差异；自动调阻每两秒最多变化一个设备增量，不要求瞬间到达目标。

- [ ] **C12 导出记录与诊断**\
  在「记录」导出摘要 CSV 和完整备份 ZIP；打开刚保存的一次记录，导出明细 CSV。在「设置 → 设备诊断」导出诊断日志。用系统文件管理器确认文件确实保存。\
  通过标准：文件非空、可以打开；摘要对应此次运动，明细含多行采样，未知指标可以为空；诊断 TXT 含 App／Android／设备信息。保存文件中途按取消也不应卡住 App。跨设备导入见 D01–D03。\
  手机：未测；平板：未测。

## 出现问题时如何取证

**连接、阻力或数据异常**：在「设置 → 设备诊断」确认「记录蓝牙协议报文」已启用（alpha.6 默认开启），重新做一次最短复现步骤；若是连接问题，应在重新搜索／连接前开启。复现后尽快导出「诊断日志」；如不希望继续记录报文，可关闭该选项。日志只保留近期内容，不要等到做完所有测试才导出。

**界面问题**：截图尽量保留整个屏幕，注明横竖屏、字体／显示大小、语言、主题及是否分屏。若是悬浮窗、跳动、误触或状态丢失，短录屏通常更容易定位。

**保存或导入问题**：注明文件类型、来源 App 版本、导入次序、是否修改过 CSV，以及实际错误提示。先保留原文件；不必为了复现删除真实记录。

同一问题分别记录「尝试次数／出现次数」。例如「3 次中 2 次」，比「偶尔出错」更便于排查。日志可命名为 `小米14-C04-日期时间.txt`；尽量记录异常发生的本地时刻。分享前检查内容，诊断一般不需要整份运动备份；协议报文可能含实时传感器读数。
