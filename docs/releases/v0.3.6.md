# v0.3.6

[下载普通版 / Download regular APK](https://github.com/q1ngyang/open-mobifitness/releases/download/v0.3.6/OpenMOBI-0.3.6.apk) · [Debug 复测包 / Debug retest APK](https://github.com/q1ngyang/open-mobifitness/releases/download/v0.3.6/OpenMOBI-0.3.6-debug.apk) · [English](#english)

- 修复 Issue #2 的迟到档位反馈：发送成功后的 5 秒等待窗口结束时保留最新目标，之后收到匹配的有效设备读数即可消除“尚未确认”提示。缺失、越界、缓存读数和设定值不能冒充设备反馈；MB-EP 的有效范围仍为 1–24。
- 新请求替换旧目标；连续同值请求、断连重连和控制失效都有独立的任务生命周期保护。不会因未收到档位确认而自动重连或恢复失效指令。
- 保留自动训练逐档调节。同一阶段没有新有效反馈时不重复发送同一目标；收到有效反馈或切换阶段后重新判断。手动改档退出自动模式，并可从最新未确认目标继续加减。
- 设备页与训练页统一区分发送中、等待反馈、尚未确认、设备读数一致和发送失败；六种语言同步更新。真实 GATT 写失败、FTMS 拒绝和控制点超时仍按错误处理。AT-R、HuanTong 的只写设定与必要周期写入保留。
- 诊断补充请求 ID、目标、发送状态与有效反馈版本，方便核对连续操作和迟到反馈。

版本代码为 16，普通版与 Debug 版沿用原包名和签名。数据库版本 9、训练 CSV 格式 7 保持兼容。Debug 与普通版数据独立；日常使用请选择普通版，复测时先断开另一版的器材连接。

修复覆盖共用调阻流程，没有新增型号的硬件认证。V1 回包不带请求序号，本地请求 ID 仅用于任务管理；读数一致不能证明同值回包的确切归属，也不能证明机械阻力已经变化。**机械阻力实机验收尚未完成，Issue #2 保持开放。**

## English

- Fixes late resistance feedback in Issue #2. The latest target survives the five-second feedback window, and a later matching valid device reading clears the unconfirmed notice. Missing, out-of-range, cached and commanded values cannot confirm a request; MB-EP remains limited to levels 1–24.
- New requests replace old intent. Repeated equal targets, reconnections and control invalidation are protected by request lifecycles. Missing resistance confirmation does not trigger reconnection or replay invalidated commands.
- Automatic plans retain one-level adjustments. Without new valid feedback, a stage does not repeatedly send the same target. Fresh feedback and stage changes allow reevaluation. Manual changes leave automatic mode and can continue from the latest unconfirmed target.
- Devices and Training share sending, awaiting-feedback, unconfirmed, matching-reading and send-failure states in all six languages. Actual GATT failures, FTMS rejections and control-point timeouts remain errors. AT-R/HuanTong commanded levels and required periodic writes are preserved.
- Diagnostics add request IDs, targets, transmission state and valid-feedback revisions for investigating overlapping requests and late readings.

Version code 16 retains the existing regular/Debug package IDs and signing identities. Database version 9 and session CSV format 7 remain compatible. Debug and regular data stay separate; use the regular app daily and disconnect the other variant before equipment retesting.

Release verification passed all 541 core/Debug/Release tests with no failures or skips, six-language resource checks and both lint tasks (zero errors, 91 warnings and one hint each). Regular, Debug and instrumentation APKs built successfully. Both app certificates match v0.3.5, and all packaged 64-bit libraries passed ZIP/ELF 16 KiB alignment checks. API 34 in-place updates from v0.3.5 preserved both variants' UIDs, first-install times, databases and preferences. Local evidence is in `$DEV_TEMP_BASE/work/openmobi-v036-20261024/`; the earlier fix review includes 20 individually inspected Chinese/German screenshots. Private original logs remain local. Release assets include both APKs and SHA-256 checksums.

These changes cover shared resistance control and do not certify additional hardware models. V1 replies have no request sequence number; local IDs manage tasks only. Matching telemetry cannot establish exact attribution of equal-target replies or prove mechanical resistance execution. **Hardware acceptance remains pending and Issue #2 stays open.**
