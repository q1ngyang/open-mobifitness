# 验证与设备反馈

手机和平板的逐项操作、通过标准与反馈模板见 [实机测试清单](DEVICE_TEST_CHECKLIST.md)。

## 自动检查

```sh
python3 tools/check_resources.py
./tools/build.sh :core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest
```

协议测试覆盖 V1 状态模板和磁阻椭圆机双脉冲踏频、V2 数字位数字段、FTMS SINT16、能力范围、可选字段与截断数据包；数据测试覆盖 CSV 特殊字符、公式文本、备份往返、去重、冲突事务回滚、中断恢复。

`ExerciseFlowTest` 在 Android 上使用明确标注的模拟器材运行完整训练 → 悬浮面板 → 返回运动页 → 保存记录。它不验证真实 BLE 或电机行为。运行前仅对测试应用授予悬浮权限：

```sh
adb shell appops set org.openmobifitness.app.debug SYSTEM_ALERT_WINDOW allow
./tools/build.sh :app:connectedDebugAndroidTest
```

`LanguageLayoutTest` 在运动中切换全部六种语言，检查 Activity 重建后的界面文本与同一个会话 ID，并保存运动页截图。可通过 instrumentation 参数 `layout` 标记截图尺寸。

## 0.1.0-alpha.3 验证结果

- 22 项 core 测试、10 项 Android JVM 测试通过；其中 6 项新 BLE 测试覆盖用户所报 FFE3 / FFE4 特征拓扑、AB 状态解析、设备反馈确认、现代与旧回调入口、订阅失败、畸形报文及断开后的迟到回调。
- 用户提供的 34 条实体 MB-EP / 子类型 17 通知在本地全部回放通过：识别 1–24 档、读取当前阻力、按双脉冲换算踏频、解析心率，调阻编码保留设备配置字段。原始报文未提交仓库。**没有执行实体机械调阻；该部分仍待用户安装新版后复测。**
- 192 个资源键、六种语言完整集合与格式参数检查通过；Android Lint 无错误。
- Android 14 / x86_64 模拟器，1024 × 768 dp 平板：滑块提交、手动覆盖自动方案、暂停冻结时长／距离／热量／倒计时、小窗拖动与展开、收起、返回同一运动、结束保存通过。
- 同一模拟器 320 × 640 dp 手机、深色主题重复训练／滑块／两级悬浮窗／保存流程通过；检查实际截图中的数值、单位和操作按钮。
- 320 × 640 dp 手机、130% 字体下六语言运动页检查通过，验证距离／热量数值可见高度、加减按钮和悬浮入口；切换语言保持同一暂停会话。
- 平板上指标排序、三种显示范围选择、Activity 重建后配置和会话保留、四类演示器材单位、地址脱敏与协议日志开关验证通过。
- 经系统文件选择器导出 report 3，读取 Downloads 中实际文件并校验版本与正文通过。平板选择器中的同名标题造成旧测试定位不准，已改为定位侧栏根目录条目后重跑通过。
- 使用原发行密钥签名；模拟器中从 alpha.2 覆盖安装到 alpha.3 成功，首次安装时间保持不变；APK ZIP 和 arm64-v8a / x86_64 原生 ELF LOAD 段的 16 KiB 对齐检查通过。

本轮软件模拟器冷启动出现系统蓝牙／System UI ANR，最初的悬浮窗检查被系统对话框遮挡而失败；关闭对话框、待系统稳定后重跑上述流程通过。失败运行保留在本地测试日志，不计为通过。模拟器仅验证 UI 和软件状态，不验证蓝牙无线链路、器材电机或 vivo 后台策略。本轮实机优先复测步骤见 [清单开头](DEVICE_TEST_CHECKLIST.md#alpha3-优先复测先在平板完成)。

## 0.1.0-alpha.2 验证结果

- 21 项核心测试和 4 项 Room / 备份 / 迁移测试通过。覆盖四种 FTMS 数据报文的新增字段和截断边界、V2 热量、估算来源、暂停／重置／重连累计、倒计时、阻力百分比、CSV v1/v2 和预发布版本排序。
- 178 个资源键、六种完整语言集合与格式参数校验通过；Android Lint 无错误。
- Android 14 / x86_64 模拟器：320 × 640 dp 手机、同尺寸 130% 字体、640 × 360 dp 横屏、1024 × 768 dp 平板及其 130% 字体，分别完成六语言切换、数值可见高度与控制按钮检查。语言切换保持同一训练和暂停状态。
- 浅色与深色下的训练 → 小悬浮窗 → 拖动 → 展开 → 收起 → 返回同一训练 → 保存记录通过。暂停后的时间、距离、热量和阶段倒计时保持不变。
- 指标排序与 Activity 重建后配置保留、四类演示器材的频率单位、地址脱敏、默认关闭／手动启用协议日志通过。日志使用唯一测试标记，避免把上次保留的报文误判为关闭记录后的新采集。
- `DiagnosticExportTest` 经 Android 系统文件选择器把诊断日志保存到 Downloads，并读取验证实际文件内容。
- 数据库 v1 → v2 升级保留原有记录及采样；CSV／ZIP 往返保留新字段。
- 发行签名、APK ZIP 和两个 ABI 的 ELF LOAD 段均通过 16 KiB 对齐检查，沿用 alpha.1 签名密钥。

检查中修复了低矮横屏的指标数值裁切、窄屏目标百分比被长标签挤掉、极短暂停后累计数据计入暂停间隔等问题。软件模拟器冷启动曾出现系统进程／桌面 ANR，相关失败不计为通过；系统稳定后重跑。跨语言 Activity 重建测试改用真实无障碍树，以避免 Compose 测试时钟等待旧界面的偶发超时。

这些是模拟器与合成报文验证，不是实体器材认证。小米 14 / Android 16、iQOO Pad 2 Pro / Android 16（用户诊断为 API 36） 的 BLE 控制、厂商后台策略与实体铰链仍待实测。部分旧划船机、HuanTong、型号相关的跑步机私有字段仍未恢复，见 [逐项能力](TRAINING.md)。

## 0.1.0-alpha.1 验证结果

- 10 项核心测试、3 项 Room / 备份测试通过；Android Lint 无错误，签名 release 构建通过。
- Android 14 / x86_64 模拟器上的悬浮控制面板往返与记录保存测试通过。
- 同一模拟器分别在 320 × 640 dp 手机窗口、1024 × 768 dp 平板窗口完成六语言切换测试；手机 130% 字体下也完成六语言检查。
- 检查了实际截图并修正窄屏控制按钮、德语长标签、数值字号与大字体指标换行。
- 发行包仅包含 arm64-v8a / x86_64 原生库，APK ZIP 与 ELF LOAD 段均通过 16 KiB 对齐检查；发行签名通过 `apksigner verify`。

这些结果来自模拟数据和 Android 14 模拟器。Android 10、Android 16、小米 / vivo 后台管理、实体器材 GATT 读写、真实铰链状态仍待实机验证。编译目标版本和静态检查不能替代这些测试。

## 首轮实体测试

器材：白色经典款 MB-EP 系列椭圆机。手机：小米 14 / Android 16；平板：iQOO Pad 2 Pro / Android 16（用户诊断为 API 36）。

1. 安装签名 alpha；可先启用飞行模式后单独开启蓝牙，确认无需账号和网络也能进入。
2. 断开官方 App，搜索并连接器材。记录设备页的协议、阻力范围，以及静止／运动时踏频和阻力显示。
3. 若控制可用，以相邻档位测试一次增加和一次降低，核对体感与显示反馈；不要先运行自动高低交替。
4. 在低强度手动训练中切换悬浮面板，打开视频 App，返回运动页，核对计时、连接和记录没有重置。
5. 暂停计时、继续、结束保存；导出 ZIP，再导入，确认不会重复记录。
6. 若无法识别或反馈不符，在「设置 → 设备诊断」按需开启蓝牙协议报文记录，复现一次后导出日志，再关闭记录；在 issue 中附上型号、App／Android 版本、现象和日志。导出内容由用户检查并主动分享。

无实体折叠屏：只验证不同窗口尺寸、旋转和配置变化，不声称已通过实体折叠铰链或厂商系统验证。其他器材同样需要逐型号补充真实反馈。
