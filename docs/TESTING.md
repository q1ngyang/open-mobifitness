# 验证与设备反馈

手机和平板的逐项操作、通过标准与反馈模板见 [实机测试清单](DEVICE_TEST_CHECKLIST.md)。

## 自动检查

```sh
python3 tools/check_resources.py
./tools/build.sh :core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest
```

协议测试覆盖 V1 状态模板和磁阻椭圆机双脉冲踏频、V2 数字位数字段、FTMS SINT16、能力范围、可选字段与截断数据包；数据测试覆盖 CSV 特殊字符、公式文本、备份往返、去重、冲突事务回滚、中断恢复。

`ExerciseFlowTest` 在 Android 上使用明确标注的模拟器材运行完整训练 → 悬浮面板 → 返回运动页 → 保存记录。它不验证真实 BLE 或电机行为。运行前仅对测试应用授予悬浮权限：

```sh
adb shell appops set org.openmobifitness.app.debug SYSTEM_ALERT_WINDOW allow
./tools/build.sh :app:connectedDebugAndroidTest
```

`LanguageLayoutTest` 在运动中切换全部六种语言，检查 Activity 重建后的界面文本与同一个会话 ID，并保存运动页截图。可通过 instrumentation 参数 `layout` 标记截图尺寸。

## 0.1.0-alpha.4 验证结果

- 25 项核心测试、14 项 Android JVM 测试通过；Debug / Release Lint 无错误。新增官方功率模型参考点、实际反馈与目标值区分、无效读数、估算来源、极端模型值 CSV 往返、v1/v2 数据库迁移、日志容量／保留时间／清空、悬浮单元格长数字与大字体测试。
- 用户最新 MB-EP 日志的 394 条状态帧在本地回放：391 条得到 0–206 W 的模型估算，其中 15 条为静止 0 W；3 条初始化时阻力为 0，按未知数据处理，未伪造功率。原始日志不提交仓库。**这是协议回放，不是对机械功率的实测或校准。**
- 222 个资源键、六种语言完整集合与格式参数检查通过；「频率」在四类演示器材上保持同一标签，单位按 rpm／spm 区分。
- Android 14 / x86_64 模拟器，按显示尺寸折算的 360×780 dp 手机、780×360 dp 手机横屏、800×1280 dp 平板竖屏、1280×800 dp 平板横屏、840×900 dp 近方形折叠窗口、320×640 dp 窄屏，以及 360×780 dp / 130% 字体完成布局与操作检查。覆盖浅／深色、阶段列表、指标翻页、调阻控件、屏幕常亮与离开后清除、始终可见的保存栏、取消结束与确认保存。迭代后重跑受影响的手机横屏、平板竖屏与折叠布局，并复核实际截图。
- 手机 130% 字体完成全部六种语言切换、控件／读数可到达性及同一暂停会话保留检查。低矮或大字体场景允许滚动，不把“可到达”混称为所有内容始终同屏。
- 手动滑块、自动调阻开关、暂停冻结时间／累计／倒计时、两级面板拖动／展开／返回／保存通过。关闭自动调阻开关不会主动更改当时阻力。
- `AutomaticOverlayTest` 验证 Home 自动小窗、返回同一训练、关闭自动开关、关闭总开关；99:59:59、99999.9 kcal 等长数据不改变小窗／大窗边界。`FloatingSettingsTest` 从实际设置列表定位开关，验证关闭、界面重建、持久化、总开关禁用自动开关与重新开启。
- 指标选择／排序、三个范围、界面重建后配置保留、日志脱敏与协议记录开关通过。`DiagnosticExportTest` 经系统文件选择器导出 report 4，读取实际文件并检查版本和小于 128 KiB 的上限。
- 沿用原发行密钥，alpha.3 → alpha.4 覆盖安装与启动成功，首次安装时间保持不变。该模拟器发行包原数据库为空；另用同一签名 alpha.4 在 Android 上迁移合成 v2 数据库，逐列确认 1 条训练、2 条采样、1 套方案保持原值，新功率来源标记为 false。v1 与 v2 的非空迁移另有 JVM 测试。
- APK ZIP 与 arm64-v8a / x86_64 原生 ELF LOAD 段均通过 16 KiB 对齐，发行签名校验通过。

设计稿和实际布局说明见 [UI 设计](UI_DESIGN.md)。检查中修正了大计时挤掉目标、估算符号行高导致数字变小、手机横屏滑块被挡、近方形窗口留白等问题；修正德语大字体保存标签裁切，并增加实际文字布局溢出断言；设置列表的测试改用虚拟列表滚动定位后通过，早期失败运行不计为通过。

模拟器不能验证 MB-EP 的无线链路、功率估算与官方实机表现是否一致、vivo / 小米后台策略或实体铰链。请优先复测 [A01–A06](DEVICE_TEST_CHECKLIST.md#alpha4-优先复测先在平板完成)，无需重做全部清单。

- 192 个资源键、六种语言完整集合与格式参数检查通过；Android Lint 无错误。

- 320 × 640 dp 手机、130% 字体下六语言运动页检查通过，验证距离／热量数值可见高度、加减按钮和悬浮入口；切换语言保持同一暂停会话。
- 平板上指标排序、三种显示范围选择、Activity 重建后配置和会话保留、四类演示器材单位、地址脱敏与协议日志开关验证通过。

## 首轮实体测试

器材：白色经典款 MB-EP 系列椭圆机。手机：小米 14 / Android 16；平板：iQOO Pad 2 Pro / Android 16（用户诊断为 API 36）。

1. 安装签名 alpha；可先启用飞行模式后单独开启蓝牙，确认无需账号和网络也能进入。
2. 断开官方 App，搜索并连接器材。记录设备页的协议、阻力范围，以及静止／运动时踏频和阻力显示。
3. 若控制可用，以相邻档位测试一次增加和一次降低，核对体感与显示反馈；不要先运行自动高低交替。
4. 在低强度手动训练中切换悬浮面板，打开视频 App，返回运动页，核对计时、连接和记录没有重置。
5. 暂停计时、继续、结束保存；导出 ZIP，再导入，确认不会重复记录。
6. 若无法识别或反馈不符，在「设置 → 设备诊断」按需开启蓝牙协议报文记录，复现一次后导出日志，再关闭记录；在 issue 中附上型号、App／Android 版本、现象和日志。导出内容由用户检查并主动分享。

无实体折叠屏：只验证不同窗口尺寸、旋转和配置变化，不声称已通过实体折叠铰链或厂商系统验证。其他器材同样需要逐型号补充真实反馈。
